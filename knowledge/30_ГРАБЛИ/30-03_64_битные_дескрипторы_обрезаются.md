# 64-битные значения в ctypes

## Что происходит
`ctypes.windll.user32.SendMessageW(...)` возвращает C `int` (32 бита).
HTREEITEM, HWND и указатели на 64-битной Windows — 64-битные. Старшие
биты теряются: `TVM_GETNEXTITEM` возвращает «узел», который указывает не
туда, выбирается соседний или нулевой узел; ошибки нет.

## Как правильно
Использовать `hdkit` (все функции описаны в `hdkit/_win.py` с argtypes и
restype: `c_ssize_t` для LRESULT, `c_void_p` для дескрипторов). Свои вызовы:
отдельный экземпляр `ctypes.WinDLL("user32")` с заданными типами (общий
`ctypes.windll.user32` могут менять другие модули).

## Как неправильно
`ctypes.windll.user32.SendMessageW(tv, 0x110A, 4, node)` без типов;
передача `byref(buf)` как lParam в сообщение другому процессу (адрес чужому
не годится — [10-03](../10_API/10-03_управление_сообщениями.md),
RemoteBuffer).

## Чем подтверждено
Designer: до исправления выбирался корневой узел вместо нужного региона,
после — нужный; msinfo32: `tree_path` даёт дескриптор вида 0x212dd690750.
