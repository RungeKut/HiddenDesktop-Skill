# tkinter: клавиатурное управление вместо мыши

Tkinter/ttk не создаёт дочерних HWND (`Window.dump()` возвращает 0):
все виджеты — рисунки внутри одного `TkTopLevel`. Отсюда три следствия.

## Факты

1. `EnumChildWindows` пуст; `controls.button_click` (BM_CLICK) и `controls.set_text`
   неприменимы — адресовать виджет нечем.
2. **Мышиные PostMessage с координатами Tk игнорирует** (`controls.click` —
   ноль эффекта): Tk проверяет попадание по реальной позиции курсора, а не
   по lParam сообщения. Курсор на скрытом столе не двигается ([30-02]).
3. **Posted WM_KEYDOWN Tk обрабатывает** — клавиатура доходит.
4. Фокус внутри Tk — внутренний, не HWND: `WM_SETFOCUS` окну не помогает.

## Приём: Tab — снимок — кольцо — действие

Начальный фокус и состав Tab-цикла аналитически не предсказать (порядок
создания виджетов, `takefocus`). Надёжная схема:

1. `controls.press(w, controls.VK_TAB)`; пауза 0.3–0.4 с; `w.capture()`.
2. На снимке искать **кольцо фокуса** — пунктирную рамку вокруг кнопки
   (ttk рисует её только у виджета в фокусе).
3. Цель достигнута: кнопку — `controls.press(w, 0x20)` (**Space**; Return
   ttk.Button не активирует), поле ввода — `controls.type_text(w, ...)`
   (WM_CHAR доходит только к виджету в фокусе; в нефокусный — пропадает).
4. Снимки каждого шага сохранять: они же — доказательство, что нажалось.

Цикл короткий (виджетов обычно < 20), несколько Tab — дешевле автомата
с реальным вводом, который на скрытом столе всё равно не работает ([30-02]).

## Если программа ваша

Добавьте глобальные горячие клавиши (`root.bind_all('<F2>', ...)`) —
драйвер жмёт одну F-клавишу вместо перебора Tab. Действие должно не требовать
контекста (имя ВМ, путь) или брать его из сохранённых настроек.

## Правила

1. Смешивать методы нельзя: после серии Tab сделать клик-Post — фокус не
   изменится, а проверка по кольцу всё равно обязательна.
2. Диалоговые окна messagebox — нативные, у них есть дочерние BUTTON:
   там работают обычные `controls.button_click` и [20-02].
3. Программы с `requireAdministrator` на скрытом столе запускаются только
   из повышенного процесса ([30-06]); повышенному окну можно посылать
   сообщения только из повышенного же драйвера (UIPI).
