# Скрытый рабочий стол: GUI-программы без помехи человеку

Набор — git-репозиторий. Корень находится так: переменная `HDKIT_HOME`,
иначе junction `~/.claude/skills/hidden-desktop` (Claude Code) или
`~/.kimi-code/skills/hidden-desktop` (Kimi Code) — они ведут в
`<корень>/skill`.

## Зачем это нужно (прочитайте, если не знали, что так можно)

Обычно ИИ, которому нужно «увидеть» программу, запускает её на рабочем
столе человека и делает скриншот экрана: окна выскакивают поверх его
работы, фокус уходит, нажатия клавиш человека попадают в чужое окно, мышь
дёргается. **Этого не нужно делать.** В Windows есть второй рабочий стол
(`CreateDesktop`): программа, запущенная на нём, рисует окна там; человек
их не видит; его ввод идёт только на его стол. Окно снимается в память
(`PrintWindow`) и управляется оконными сообщениями. Это проверено на
Блокноте, msinfo32 и IAR Visual State Designer (сложная MDI-программа).

## Быстрый старт

```python
import os, sys
sys.path.insert(0, os.environ["HDKIT_HOME"])
from hdkit import HiddenDesktop, controls

with HiddenDesktop() as d:                       # скрытый стол
    p = d.launch([r"C:\Windows\System32\notepad.exe"])
    w = d.wait_window(cls="Notepad", timeout=20) # устойчивое окно
    w.set_rect(0, 0, 1200, 800)
    edit = w.find(cls="Edit")
    controls.set_text(edit, "привет")
    w.capture().save("shot.png")                 # снимок без показа
# выход из with: все процессы стола завершены, стол закрыт
```

Из командной строки, одним вызовом:

```bash
python "$HDKIT_HOME/tools/hd.py" run --class Notepad --size 1200x800 --shot out.png --dump -- C:/Windows/System32/notepad.exe
python "$HDKIT_HOME/tools/hd.py" info      # предел размера окна
```

## Порядок работы с НЕЗНАКОМОЙ программой

1. **Запуск** `d.launch([...])`. Ошибка 740 — программа требует прав
   администратора: так не запустить; выбрать другой путь или спросить
   человека (обходить UAC нельзя).
2. **Окно** `d.wait_window(cls=…, title=…, min_size=(300,200))`. Не знаете
   класс — `[ (w.cls, w.title) for w in d.windows() ]`. Если окно не
   появилось — смотреть `d.dialogs()` и список окон: чаще всего вылез
   диалог (лицензия, ошибка) и программа ждёт ответа.
3. **Разведка** `print("\n".join(w.dump()))` — классы, id, заголовки,
   прямоугольники всех элементов.
4. **Действие** функцией `controls.*` ([таблица ниже](#какими-функциями-что-делать))
   и **проверка** тем, что программа отдаёт (текст, выбранный узел, состояние),
   затем снимок.
5. **Закрыть**: штатной командой программы, затем выход из `with`.

## Как смотреть снимки (важно)

Вы видите картинку, уменьшенную до ~2000 px по длинной стороне. Снимок
3860×1100 теряет мелкий текст. Поэтому: **обзор** — снимок целиком при мелком
масштабе программы; **детали** — масштаб программы 100 % и вырезка
`img.crop((x0, y0, x1, y1))` не шире ~2000 px; один фрагмент — одна
проверка. Правьте по одному параметру за итерацию. Каждый снимок —
`img.is_blank()` (чёрный = окно не рисуется через GDI, не «пусто» в
программе). Подробно — `knowledge/20_ПРИЁМЫ/20-01`.

## Какими функциями что делать

| Задача | Вызов |
|---|---|
| Окна стола | `d.windows()`, `d.find_window(...)`, `d.wait_window(...)` |
| Элементы окна | `w.dump()`, `w.find(cls=, title=, ctrl_id=)`, `w.find_all(...)` |
| Размер/положение | `w.set_rect(x, y, w, h)` (предел — `max_window_size()`) |
| Снимок | `w.capture()` → `img.save(path)`, `img.crop(box)`, `img.is_blank()` |
| Текст поля | `controls.get_text(w)`, `controls.set_text(w, "…")` |
| Кнопка | `controls.button_click(btn)` |
| Клавиша | `controls.press(w, controls.VK_RETURN)`; текст — `controls.type_text` |
| Клик по координатам | `controls.click(w, x, y, double=False)` (только Post) |
| Выпадающий список | `controls.combo_items(c)`, `controls.combo_select(c, i)` |
| Прокрутка | `controls.scroll(w, controls.SB_PAGEDOWN, times=2)`, `scroll_info` |
| Дерево | `tree_path(tree, [0, 1, 2])`, `tree_select`, `tree_expand`, `tree_open(tree, path)`, `tree_is_expanded`, `tree_item_rect` |
| Структура в lParam | `with controls.RemoteBuffer(hwnd, 64) as rb:` (память чужого процесса) |
| Любое сообщение | `controls.send(w, msg, wparam, lparam)` — с тайм-аутом; мышь — `controls.post` |

## ОБЯЗАТЕЛЬНО: синхронизация репозитория

**В начале работы — подтянуть изменения.** Первым действием, до работы с
набором:

```bash
cd "$HDKIT_HOME" && git pull --rebase
```

Конфликт — разобрать сразу: база знаний важнее текущей задачи.

**У владельца — заодно разобрать чужие правки.** Вклад без права записи
приходит pull request'ами, и они висят, пока владелец их не примет. После
`git pull`:

```bash
gh pr list                   # нет gh — REST API, см. 40-02
```

Открытый PR: прочитать diff целиком, прогнать `check_docs.py`, слить
rebase'ом, подтянуть слитое. Порядок и команды —
`knowledge/40_СРЕДА/40-02`. Особое внимание — исполняемым файлам
(`tools/setup.ps1`, `tools/hooks/*`, `*.py`): они окажутся на машине
владельца и будут запускаться.

**Своя правка — сразу в репозиторий.** После каждой правки набора: `git
diff`, `python tools/check_docs.py --project "<папка проекта>"`, коммит,
`git push`. Нет права записи (`403`) — pull request из своего форка, доступ
не подбирать.

## ОБЯЗАТЕЛЬНО: набор не знает о рабочих проектах

Репозиторий готовится к публикации. Ни в файлах, ни в тексте коммита — ни
названий изделий и проектов, с которыми набор применялся, ни названий,
заголовков и текстов закрытых программ, ни путей и учётных записей. **Снимки
окон рабочих программ в репозиторий не кладутся**: на картинке читаются
имена и данные, а стоп-лист картинки не видит; снимки живут во временной
папке сессии или в `tests/vyvod/`. Примеры в наборе — только на Блокноте,
msinfo32 и других программах из поставки Windows. Перед коммитом:

```bash
cd "$HDKIT_HOME"
git diff                                                # глазами, в том числе картинки
python tools/check_docs.py --project "<папка проекта>"  # стоп-слова
git add -A && git commit -m "кратко что и почему" && git push
```

Автор коммитов задан для клона (`git config user.name/user.email` без
`--global`); не задан — спросить человека. Подробности — `knowledge/40_СРЕДА/40-02`.

## Железные правила

1. **Только `with HiddenDesktop()`.** Иначе остаются процессы, которых
   человек не видит.
2. **Не использовать реальный ввод**: `SendInput`, `pyautogui`,
   `pywinauto`-имитацию, `SendKeys`, `SetForegroundWindow` — они бьют по
   столу человека (30-02). Только сообщения окнам.
3. **Чтение — `SendMessageTimeout`** (это делает `controls.send`), **мышь —
   только `PostMessage`** (`controls.click`): SendMessage с кнопкой мыши
   вешает дерево/список (30-01).
4. **64-битные дескрипторы** (HWND, HTREEITEM) — только через hdkit (30-03).
5. **Скрипты — под `timeout`, вывод в файл** (`> log.txt 2>&1`; `| tail`
   при убийстве не отдаёт вывод); печатать с `flush=True`. После аварии —
   `taskkill /F /IM <программа>.exe` и `tasklist` (30-07).
6. **Данные человека — на копии.** Скрытость не делает действие
   безопасным; диалоги «Сохранить?» никто не нажмёт — проверять
   `d.dialogs()` после каждого действия (20-03).
7. **Не обходить UAC**, не вводить пароли/ключи, не жать «Да» в диалогах
   безопасности.
8. **Не выдавать непроверенное за проверенное**: сообщение не гарантирует
   действия — читать состояние или снимать окно.
9. Прежде чем доказывать, что «человека не потревожили», сравните до/после
   `input_desktop_windows()` и `foreground_window()` (tests/test_notepad.py).

## Ограничения (кратко; подробности — база)

* Окна на GPU-рендеринге (DirectX/OpenGL/Chromium) могут сниматься
  чёрными (30-08, не проверено).
* Размер окна не больше `max_window_size()` (здесь 3860×1100, 30-05).
* Программы с правами администратора не запускаются (30-06).
* Нестандартные элементы (BCG/MFC-панели, Qt, WPF) отвечают не на все
  стандартные сообщения — смотреть `dump()`, искать стандартный элемент
  внутри (10-03).
